# פוקר שכונתי – סיכום משחקים 🃏

אפליקציית ווב לניהול וניתוח משחקי פוקר שכונתיים מקובץ Excel.
מעלים קובץ, המערכת שומרת רק שורות חדשות (ללא כפילויות), והדשבורד מציג
אינפוגרפיקה חיה בעברית — בסגנון שולחן פוקר ירוק־זהב.

מיועד לרוץ תחת: `powdercoat.co.il/playgames`

לפריסה תחת נתיב המשנה, הגדירו לפני ה־build:

```bash
NEXT_PUBLIC_BASE_PATH=/playgames npm run build
```

(בפיתוח מקומי אין צורך — האתר רץ בשורש.)

### פריסה לשרת (Hetzner)

**הפריסה אינה אוטומטית, וה־workflow הפעיל אינו בריפו הזה.** הוא יושב ב־
`galrighter/powdercoat-site` (‏`.github/workflows/deploy-playgames.yml`), כי
secrets ב־GitHub הם per-repo ומפתח ה־SSH ל־Hetzner קיים שם. אותו workflow עושה
checkout ל־`galrighter/social-agent` — השם הישן של הריפו הזה, שעדיין מפנה אליו —
ולכן הוא בונה את הקוד שב־`main` כאן.

מה שהוא עושה: build כ־standalone עם `basePath=/playgames`, ‏rsync ל־
`/opt/playgames/app`, מיגרציית Prisma על `/opt/playgames/data/prod.db`, והפעלה
מחדש של שירות `playgames` (systemd, פורט 3017). ‏nginx בשרת מפנה את
`powdercoat.co.il/playgames` לאפליקציה (ה־include יושב ב־vhost של powdercoat-site).

**איך פורסים:** קומיט ב־`powdercoat-site` שנוגע ב־`deploy/.playgames-trigger`
על `main` (שורת תיאור + חותמת זמן — כך נעשו כל הפריסות), או הרצה ידנית של
ה־workflow שם דרך workflow_dispatch. מיזוג ל־`main` בריפו הזה **לא** פורס כלום
בפני עצמו.

העותק של `deploy-playgames.yml` שבריפו הזה הוא fallback ליום שבו יתווסף כאן
secret בשם `HETZNER_SSH_KEY` — הוא `workflow_dispatch` בלבד, וכל הרצותיו נכשלו
בהיעדר המפתח.

## התקנה

```bash
npm install
npx prisma migrate dev
npm run dev
```

הפקודה `npx prisma migrate dev` יוצרת את מסד הנתונים (SQLite מקומי,
`prisma/dev.db`) ומזריעה אוטומטית את תיקוני ברירת המחדל.

האתר יעלה בכתובת: http://localhost:3000 (הדף הראשי מפנה ל־`/dashboard`).

## איך מעלים Excel

1. נכנסים לעמוד **ייבוא Excel** (`/import`).
2. גוררים את הקובץ לאזור ההעלאה או בוחרים קובץ.
3. אם הקובץ מוגן בסיסמה — יופיע שדה להזנת סיסמת הקובץ, והייבוא ימשיך
   אוטומטית עם אותו קובץ (ראו למטה).
4. בסיום מוצג סיכום: כמה שורות נקראו, כמה נוספו, כמה דולגו (כבר קיימות),
   כמה לא תקינות וכמה תיקוני נתונים הופעלו.

**חשוב:** העלאה חוזרת של אותו קובץ לא יוצרת כפילויות. כל שורה מקבלת
`rowHash` יציב (שם + טלפון + סוג + סכום + תאריך + הערות), ושורה שכבר
קיימת במסד פשוט מדולגת. קובץ חדש שמכיל גם שורות ישנות וגם חדשות —
רק החדשות ייכנסו.

## קבצים מוגני סיסמה

אפשר להעלות קובץ Excel שנעול בסיסמה ("הצפן באמצעות סיסמה" ב־Excel), בלי
להסיר ממנו את ההגנה קודם. מעלים את הקובץ כרגיל; אם הוא מוצפן, המערכת מזהה
זאת ומציגה שדה סיסמה — מזינים את סיסמת הקובץ ולוחצים **פתיחה וייבוא**, והקובץ
נפתח ומיובא. סיסמה שגויה מציגה הודעה ומאפשרת ניסיון נוסף מיד, בלי לבחור את
הקובץ מחדש.

נתמכות שתי שיטות ההצפנה של Office (ECMA-376 agile ו־standard) וכן קובצי
`xls` ישנים מוצפנים. הפענוח מתבצע בשרת בזיכרון בלבד: הסיסמה אינה נשמרת
במסד, אינה נכתבת ללוג ואינה חוזרת ללקוח — רק תוכן הקובץ המפוענח נקרא.

## מבנה הקובץ הנתמך

הקובץ יכול לכלול כמה גיליונות — כולם נקראים. עמודות נתמכות:

| עמודה | הסבר |
|---|---|
| שם | שם השחקן (עברית או אנגלית) |
| פלאפון | מספר טלפון — משמש לזיהוי ייחודי של שחקן |
| סוג | `payment` = תשלום כניסה / ריבאיי, `redeem` = העברת זכייה |
| סכום | חיובי = תשלום כניסה, שלילי = זכייה ששולמה |
| תאריך | תאריך Excel או טקסט (`23/03/2024 23:33`, `2024-03-23 23:33:21`) |
| הערות | אופציונלי |

שורות ריקות מדולגות. שורה בלי שם, סכום או תאריך תקין נספרת כ"לא תקינה".

## איך מחושבים משחקים

המשחקים מזוהים לפי **אשכולות של תשלומי כניסה**:

1. כל שורות ה־payment ממוינות לפי זמן.
2. פער של יותר מ־12 שעות בין תשלום לתשלום פותח משחק חדש.
3. לכל משחק מחושבים: זמן התחלה וסיום, מספר שחקנים ייחודיים,
   סך הכניסות, ומספר כניסות (סך הכניסות חלקי ‎25 ש"ח — מחיר כניסה רגילה).

## מצב עדין להצגת הפסדים

בדירוג המלא קיים מתג **מצב עדין / מצב רגיל** (ברירת מחדל: עדין):

- **מצב עדין** — שלושת סכומי ההפסד הכוללים הגדולים ביותר לא מוצגים
  (מופיע "—" במקומם), אבל השחקנים נשארים ברשימה לפי שם ודירוג.
  בנוסף, פאנל ההפסדים מציג "ממוצע הפסד למשחק" ולא סכומי הפסד כוללים.
- **מצב רגיל** — כל הסכומים מוצגים.

## תיקוני נתונים

בעמוד `/settings/corrections` אפשר להוסיף, לכבות ולהדליק תיקונים.
תיקון מגדיר תנאי התאמה (שם, טלפון, סוג, תאריך מדויק, סכום) ותוצאה:
סכום אפקטיבי חדש ו/או החרגה מהסטטיסטיקות. התיקונים מוחלים בזמן הייבוא
ומחושבים מחדש על כל המסד בכל שינוי.

מובנים מראש (seed) שני תיקונים לטעות ההקלדה מ־23.3.2024:
תשלום של 2500 שמחושב כ־25, ושורת האיזון של ‎-2475 שמוחרגת מהסטטיסטיקות.
הדשבורד מציג את הנתונים המתוקנים באופן טבעי; פירוט התיקונים נראה רק
במסכי הניהול.

## API

- `POST /api/import` — העלאת קובץ Excel (multipart: `file`, ו־`password`
  אופציונלי לקובץ מוגן). קובץ מוצפן ללא סיסמה או עם סיסמה שגויה מחזיר 400 עם
  `passwordRequired: true`
- `GET /api/import-batches` — היסטוריית ייבוא
- `GET /api/transactions` — עסקאות עם סינון וחיפוש
- `GET /api/stats?from=YYYY-MM-DD&to=YYYY-MM-DD&softMode=true` — סטטיסטיקות
- `GET/POST /api/corrections` — תיקוני נתונים
- `DELETE /api/dev/reset-db` — איפוס מסד (development בלבד)
